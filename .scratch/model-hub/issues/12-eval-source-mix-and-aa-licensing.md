# 评测数据源组合与 AA 授权策略

Type: grilling
Status: resolved
Blocked by: 01

## Question

在 AA 条款禁止站内嵌入原始数据、也禁止用于模型 / 供应商选择指导的前提下，首版的评测数据组合怎么定？

需要定下：

- **基线**：是否采用「models.dev + Arena HF 嵌入 + AA 外链」作为最低风险方案；还是向 AA 申请书面许可 / 商业协议；或完全放弃 AA；或采用更保守的「只 models.dev + 外链」。
- **AA 外链形态**：如果只外链，产品如何呈现 AA（模型详情的外链卡片、榜单入口、说明文案），如何避免用户误以为站内分数来自 AA；是否需要为 AA 单开一个「外部评测」区。
- **Arena 子集**：用 text / text_style_control / webdev / agent 中的哪些；是否以 webdev 为主（用户原始参考）；如何处理推理档位是独立行的问题。
- **补充来源**：是否纳入 LiveBench、SWE-bench 等免费源；首版建议不纳入，除非它们能显著补足 AA 的空缺且许可清晰。
- **许可路径**：如果选择向 AA 申请，谁负责、时间 / 预算边界是什么；失败后的回退是什么；这是否改变「首版不付费、不抓取」的默认约束。
- **对下游的影响**：这个选择会改变「评测指标与缺失数据策略」的指标集合与默认排序，也会影响「收录规则与首批模型清单」的纳入标准。

约束：数据源事实见「数据源可得性、授权与字段」及其研究笔记；首版默认不付费、不抓取。产出是一个明确的选择 + 回退方案 + 对页面文案 / 指标的影响说明。

## Answer

**决定（2026-10-26）**

- **AA**：首版只做外部参考。模型详情展示明确标注「外部评测 · Artificial Analysis」的链接卡片，榜单页放 AA 总榜入口；站内不出现 AA 分数、不调用 AA API、不用 AA 排序。逐模型链接只在有稳定公开 URL 时出现，否则回退 AA 总榜。本 effort 不申请许可、不付费；MVP 验证后，如果用户明确需要 AA 的 Intelligence / Coding / 速度维度，或 AA 主动开放许可，再评估书面许可 / 商业协议。
- **Arena**：只嵌入 `text` + `webdev` 两个子集，使用 `latest` split；展示 rating / rank / 置信区间；不做跨榜比较，不把 Arena Score 当成跨榜统一分。`agent`、`text_style_control` 等其余子集首版不做。
- **补充源**：LiveBench、SWE-bench 等首版不纳入；后续按用户需求评估。
- **产品含义**：站内评测的主叙事是 Arena（通用 + webdev），AA 是可追溯的外部参考，不是站内数据。评测页仍需明确来源、更新时间、Arena 不跨榜比较的说明。
- **下游影响**：领域模型需要保存 Arena 子集 / 指标 / 置信区间 / 发布时间；需要一条 AA 外部链接的 crosswalk 字段（可为空，空则回退总榜）；评测指标票只消费 Arena `text` + `webdev`，不再为 AA 站内指标设计列 / 排序；合规票需覆盖 Arena CC BY 4.0 署名与 AA 外链文案。
